# 当前 Harness 效果基线：PR #38～#43

状态：已完成

日期：2026-07-29

本复盘是 `HARNESS.md` 建立后的第一次跨 PR 效果观察。它只建立当前 Harness 的可审计
现状，不把流程落地、绿色检查或合并数量当作正向效果证明。

## 1. 变化与假设

PR #38～#43 依次承载了 generator/evaluator 交接精简、develop 分支模型计划收尾、本地
develop 安全纯快进策略的规划与实施，以及 Harness 目的和效果评估协议的规划与实施。

待验证的假设是：这些 Harness 变化可能通过更明确的角色交接、冻结 SHA、独立验证、
受保护 PR、最终集成分支验证、安全本地更新和稳定效果评估协议，改善结果正确性、反馈
回路、可复现性、自主性与人类掌舵负担、交付效率或长期熵表现。本文只检查现有证据是否
支持这些效果，不预设假设成立。

## 3. 适用维度

本次基线观察覆盖 `HARNESS.md` 定义的全部六个维度。结果正确性、反馈回路有效性和
可复现性与可追踪性有可定位的运行事实，但这些首先是操作证据，不能直接归因为 Harness
带来的改善。自主性与人类掌舵负担、交付效率缺少可比较测量。熵与维护成本可记录当前
增减项，但尚无长期漂移观察。

## 4. 基线状态

**无可靠可比较基线。** 六个 PR 的任务异质：既有计划和收尾文档，也有脚本、测试、
导航与协议实施，不能把它们互相当作对照。历史上使用更轻 Harness 的任务在复杂度、
风险和交付内容上也不同，无法可靠反推“采用当前 Harness 前”的同类表现。

PR 从创建到合并的历时包含人类审查、批准与等待，现有记录没有把等待与实际工作时间
分开，因此不能用该历时衡量智能体效率，也不能据此估算节省比例。本文只建立
PR #38～#43 的现状基线，不补造历史耗时、干预次数、缺陷率或因果对照。

## 5. 实际结果与证据

六个 PR 的正文都记录了 generator 自检、独立 evaluator 的 `PASS`、与表中 head 相同的
冻结 SHA，以及 evaluator 前后 guard 通过的声明。这些内容是流程参与者写入 PR 正文的
交接和验证声明，不能冒充本文重新执行的独立验证。

可从 GitHub 记录独立核对的事实边界是：六个 PR 的 PR 检查成功、表中的 merge commit
存在，且每个 merge SHA 对应的最终 develop push `verify` 成功。PR 正文声明与 GitHub
可核对事实相互关联，但证据性质不同；本文不把其中任何一类单独升级为 Harness 效果。

六个维度的现状如下：

| 维度 | 观察结果 | 效果判断边界 |
|---|---|---|
| 结果正确性 | 六个 frozen head 均有成功的 PR 检查和 PR 正文中的 evaluator `PASS`、前后 guard 声明；六个 merge SHA 均有成功的最终 push `verify`。 | 这证明相应交付通过了既定操作门禁；任务异质且无同类对照，不能证明 Harness 因果性地提高了正确性，也不能推出未被验收定义覆盖的缺陷不存在。 |
| 自主性与人类掌舵负担 | PR 正文显示 generator/evaluator 角色流程得以执行。 | 没有持久、可比较的澄清次数、人工补救、微观指挥、审查往返或人类操作测量，证据不足以判断负担改善或退化。 |
| 反馈回路有效性 | PR 与最终 push 的检查链都完成并给出成功结果，说明既定反馈入口在这些交付上可运行。 | 现有样本没有可比较记录检查发现了哪些真实问题、经过多少修复轮次才收敛；操作成功不等于反馈效果相对基线改善。 |
| 可复现性与可追踪性 | 每个 PR 都能定位 frozen head、PR、merge SHA、正文验证声明和最终 push run，交付对象与证据边界可追踪。 | 这是操作上积极的可追踪信号；没有可靠基线，也没有在本复盘中重做跨环境重建实验，不能作因果改善结论。 |
| 交付效率 | 六个变更均完成受保护 PR 与最终 push 验证。 | 没有同等正确性和风险边界下的可比历时、修复轮次、等待或人工操作数据；created-to-merged 时间混入人类等待，证据不足。 |
| 熵与维护成本 | #38 合并并简化了交接协议，#39 收尾并归档了既有计划，体现了整合与精简；#40～#43 同时增加了本地更新协议、跨平台脚本、测试、Harness 目的与评估协议及导航表面。 | 当前同时存在精简收益和新增协议/测试表面；尚未观察长期文档漂移、脆弱检查、认知负担变化或后续清理量，不能判断净效果。 |

因此，结果正确性、反馈回路和可复现性上的信号是操作性的；它们支持“流程按既定方式
运行并留下记录”，不支持“相较基线发生了因果改善”。自主性与人类负担、交付效率则
因为缺少持久的可比较干预和时间测量而无法判断。

## 6. 反例与残余缺口

- 所有六个 PR 都是 Harness、流程或文档相关变更，不是同一类真实产品任务的重复样本；
- 任务规模、风险、代码与文档比例不同，不能进行 PR 间效果比较；
- PR 正文中的 generator/evaluator/guard 内容属于流程声明，本文没有把它重新验证为独立
  evaluator 报告；
- 成功检查只观察到门禁通过，没有提供失败捕获率、漏检率或同类缺陷对照；
- 没有可靠的人类干预计数、有效工作时间、等待拆分或相同任务的轻量 Harness 对照；
- 只观察到落地时点，尚未观察新协议、脚本和测试的长期漂移、维护频率或清理成本；
- 六次成功合并与最终运行可能是正确交付的必要证据，但不是正向 Harness 效果的反事实
  证明。

## 7. 维护成本

本观察单元包含六个受保护 PR。每个 PR 各有一次分支 push `verify`、一次
`pull_request` `verify`，合并后还有一次最终 develop push `verify`，合计 **18 次工作流
运行**。这是明确的运行和等待成本，只能记入成本，不能用作 Harness 有效的证明。

此外，观察单元增加或维护了角色交接、分支与本地更新协议、跨平台脚本、机械测试、
Harness 评估协议和文档导航；#38 与 #39 也通过简化、合并和归档减少了部分重复状态。
这些增减项共同构成当前维护面，尚无长期数据判断其净认知成本与漂移成本。

## 8. 结论

**证据不足。**

PR #38～#43 提供了操作上积极的信号：冻结 head、PR 检查、正文中的独立 evaluator
交接声明、merge SHA 与最终 push `verify` 可以连续定位，既定流程在六次交付中完成。
与此同时，18 次工作流运行以及新增协议、脚本和测试表面是明确成本。由于没有可靠可比
基线、任务同质性或可归因的人类负担与效率测量，本文不作正向 Harness 效果结论。

下一次观察可由人类选择一个小型真实产品任务，并在工作开始前预注册具体假设、观察维度、
基线和证据边界。这个建议只定义未来的前瞻观察方式，不授权、选择或规定任何新的产品
行为；产品范围仍须由人类另行决定并以 `SPEC.md` 为权威。
