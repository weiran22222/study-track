# `list --contains` 与精简导航后的 Harness 前瞻观察

状态：前瞻预注册，待观察

日期：2026-07-29

本文在 `list --contains <text>` 规划阶段预注册观察口径，用于跨规划 PR、功能 PR 和必要
观察收尾 PR 保存同一个产品样本的 Harness 结果。它不预写实施、evaluator、CI、PR、
合并或最终 `develop` 事实，也不预设 Harness 变化有效。

## 1. 变化与假设

被观察的 Harness 变化是[决策 026](../decisions/026-slim-agent-navigation.md)落地后的精简
入口：`AGENTS.md` 只保留目标、文档地图和根本原则，仓库修改者必须从地图跳转并完整读取
`WORKFLOW.md`；当前标准流程继续使用规格先行、最小 generator 交接、冻结 Subject SHA、
不同 evaluator 和受保护 `develop` PR。

`list --contains` 是该变化后的首个前瞻真实产品样本，而不是为了观察而扩大的 Harness 或
产品能力。待验证假设是：精简入口和明确的权威分工可能让参与者在较少非计划人工补救下
找到正确边界、完成可机械验收的实现，并留下可复现、可追踪的反馈链。本文同时主动寻找
漏读 `WORKFLOW.md`、协议漂移、越界实现、无效检查、重复工件和新增认知成本等反例。

## 2. 观察单元

观察单元从人类明确批准本规划中的产品规格与边界开始，依次覆盖：

1. 五个规划文档的 generator 起草、规划 evaluator 和规划 PR；
2. 规划合入后功能 generator 的实现、自检与修复轮次；
3. 冻结功能 Subject SHA、不同 evaluator 的 findings 与回流；
4. 功能 PR 的 review、required checks 和人类合并决定；
5. 功能合并后精确最终 `develop` SHA 的 push `verify`。

观察在上述精确最终 `develop` push `verify` 得到可定位结果时结束。随后仅由观察收尾 PR
回填和归档；收尾 PR 自身不扩展观察单元。

必须记录规格批准后仍发生的额外澄清、每次 generator 修复的触发原因、evaluator
findings、CI 失败原因、人工操作和等待边界。不得用 PR 的 created-to-merged 墙钟时间
推断智能体效率，因为其中混有人类审查、批准和不可分离的等待。

## 3. 适用维度

本观察适用 `HARNESS.md` 的全部六个维度，但证据强度不同：

- **结果正确性**：检查实现与测试是否覆盖批准规格、权限、只读和失败安全边界；
- **自主性与人类掌舵负担**：区分必需人类决定与规格批准后的非计划澄清、微观指挥和
  人工补救；
- **反馈回路有效性**：记录 generator 自检、evaluator 与 CI 是否发现真实、可行动问题，
  以及修复是否收敛；
- **可复现性与可追踪性**：检查规格、冻结 SHA、报告、PR、Actions 与最终 `develop`
  运行能否连续定位并重建验证对象；
- **交付效率**：只记录可观察的修复轮次、明确人工操作与等待边界，不估算未测量的有效
  工作时间，也不使用 created-to-merged 时间；
- **熵与维护成本**：记录新增或重复的协议、测试、运行、文档跳转、认知负担和后续清理。

## 4. 基线状态

**无可靠可比较基线。** [当前 Harness 效果基线](005-current-harness-effect-baseline.md)中的
PR #38～#43 都是异质的 Harness、流程或文档任务，不是相同复杂度和风险边界的标题搜索
产品任务；更早产品任务又使用不同流程和导航，无法构成可靠对照。

本观察只建立精简导航后首个前瞻产品样本的现状。单个样本即使按规格交付、evaluator
`PASS` 且所有 CI 绿色，也只能证明对应门禁事实和提供后续比较素材，不能证明 Harness
产生正向效果，不能倒推节省比例、缺陷率或历史人工负担。

## 5. 待记录的实际结果与证据

收尾时只填写可定位且实际发生的事实：

| 类别 | 待记录内容 |
|---|---|
| 规格批准与规划 | 人类批准边界的记录、规划 diff、规划 Subject SHA、evaluator 报告、PR 与 checks |
| 额外澄清 | 规格批准后仍需澄清的问题、提出者、原因、是否由仓库权威直接回答 |
| generator 回路 | 各阶段自检命令、失败、修复轮次、每轮根因与新 SHA；零轮也只按实际记录 |
| evaluator | 前后 guard、独立场景、findings、回流、残余缺口和最终结论，不把旧 SHA 报告复用到新 SHA |
| CI 与 PR | 功能 PR base/head、required checks、失败原因、review 纠正和人类合并决定 |
| 最终集成 | 精确最终 `develop` SHA 及其 push `verify` 的可定位结果 |
| 人工与等待 | 人工操作、开始/结束边界可明确的等待及原因；未知部分明确写未知 |

PR diff/review、Actions、冻结 SHA 和 generator/evaluator 报告优先作为权威证据；不为同一
事实补造重复 evidence 文件。规划阶段的本地环境自检和 `verify` 只在实际执行后作为
generator 自检报告，不升级为 evaluator 或远程证据。

## 6. 待记录的反例与残余缺口

收尾时无论结果是否成功，都检查并保留：

- 智能体是否漏读 `WORKFLOW.md`、误认历史工件为当前权威或需要人类指出第一跳；
- 决策、规格、计划、实现和测试之间是否漂移或复制出冲突协议；
- 是否出现超出批准搜索边界的实现、漏测、错误优先级偏差或只读副作用；
- generator 自检、evaluator 或 CI 是否给出不可行动、重复、过晚或未能发现的问题；
- evaluator 是否真正绑定冻结 SHA，修复后是否错误复用旧报告；
- 哪些正确性只能由现有 AC 证明，哪些未覆盖缺陷仍无法排除；
- 单样本、任务差异、人员差异、工具状态和等待混杂造成的不可归因部分。

没有反例也不得写成“证明有效”；必须说明观察覆盖的残余边界。

## 7. 待记录的维护成本

收尾时记录实际新增或修改的规格、决策、计划、观察、代码、测试与导航表面，以及环境
自检、定向测试、真实 JAR、完整 `verify`、evaluator 和 CI 的运行/等待成本。记录因跨
三个 PR 带来的协调与审查成本，也记录复用既有结构、检查或文档所避免的重复。

### 人类掌舵与人工补救的区分

以下属于必须保留的人类产品治理，不作为非计划补救：批准产品目标与 AC、选择字面搜索
边界、决定范围扩大或停止、审查重大取舍、决定 PR 是否合并或是否发布。

规格批准后，为重复解释已经写明的行为、指出应从导航找到的权威、纠正越界实现、手工
修改 generator 产出、微观指定本可自主完成的步骤，或因 Harness 反馈不可行动而人工
诊断，属于待记录的非计划人工补救。记录事实与原因，不预设次数越少就自动证明改善。

## 8. 待定结论

当前结论：**待定**。

观察收尾时只使用 `正向 | 混合 | 无明显效果 | 负向 | 证据不足` 之一，并说明证据与
不可归因边界。由于没有可靠可比较基线且这是首个样本，成功交付本身不能支持正向因果
结论；若无法获得可比较或可归因证据，`证据不足` 是有效且预期可接受的结论。
