# 第二次 Harness 实战复盘：并行 worktree

状态：已完成

日期：2026-07-27

## 1. 实验问题

第一次复盘确认单个无父对话子智能体可以从仓库恢复产品和架构约束，但当时没有验证并行
隔离、共享热点冲突和严格主线同步。本轮用 `show` 与 `summary` 两个只读切片验证这一缺口。

## 2. 结果

| 观察项 | 结果 |
|---|---|
| 共同基线 | 两个 worktree 均从 `1c06866` 创建 |
| 上下文恢复 | 两个子智能体均未请求产品或架构补充 |
| 分支内门禁 | `show` 39 项、`summary` 37 项测试通过 |
| 独立 PR | PR #4、#5 的初始远程检查均成功 |
| 主线同步 | `show` 合并后，`summary` 合并最新 `main` |
| 真实冲突 | 4 个，均为计划预告的共享热点 |
| 组合门禁 | 43 项测试、Checkstyle、ArchUnit、JAR 全部通过 |
| 最终远程门禁 | `main verify #26` 成功 |

实现提交分别在 21:50:15 和 21:51:23 产生，时间相差 68 秒，证明两个任务确实重叠执行。
由于 Harness 没有记录精确开始时间，本轮不能可靠计算相对串行执行的节省比例。

## 3. 哪些 Harness 机制起了作用

1. `SPEC.md` 给两个智能体提供了不可自行改写的输出、退出码和只读语义；
2. 两份执行计划明确非目标和允许的共享热点，使冲突出现时可以区分预期整合与范围漂移；
3. worktree 隔离让两个实现可以同时修改同名文件，不会在工作目录层互相覆盖；
4. Application 与 CLI 测试的并集为冲突解决提供了可执行的保留清单；
5. 严格 PR 门禁要求第二个分支同步新主线，并对新的提交图重新运行检查；
6. 子智能体复验、主智能体复验和 GitHub CI 形成三个相互独立的反馈层。

## 4. 暴露的缺口与成本

### 4.1 文档地图会漂移

两个实现都正确遵守边界，但 `ARCHITECTURE.md` 的目录地图没有列出新命令，并且仍列出一个
不存在的 CLI 测试。这不会被 ArchUnit 捕获，因为 ArchUnit 验证依赖方向，不验证文档目录。
本轮已修正文档事实；是否增加机械文档检查仍需比较长期收益与维护成本。

### 4.2 验证调用仍可能出错

主智能体第一次独立复验时，PowerShell 外层提前展开 `$env`，导致预期的 JDK 21 设置没有
生效。Maven Enforcer 准确拒绝了 JDK 17，因此产品代码没有被误判为通过。这个事件说明环境
门禁有效，也说明多层 shell 转义是验证器自身的失败源。是否增加统一的 Windows 验证入口，
应先形成新的决策卡。

### 4.3 并行不消除整合成本

两个小切片产生 4 个冲突。计划提前标出共享热点降低了判断成本，但仍需要一次子智能体解决、
一次主智能体审查和两次远程工作流。并行收益不能只看实现完成速度，还要扣除同步与复验成本。

### 4.4 每个提交触发两次远程检查

分支 push 与 PR 事件会分别运行 `verify`。这提供了重复证据，也增加等待和 CI 消耗。
改变触发策略会影响验证语义与持续成本，当前不在本实验授权范围内。

### 4.5 缺少吞吐度量

Git 提交时间只能证明重叠，不能给出开始时间、智能体活跃时长或串行基线。下一次若目标是
评估吞吐，应在计划中先定义计时点和对照方法，不能事后用聊天时间猜测。

## 5. 本轮结论

当前证据支持：

> 对边界清晰、可独立验收的切片，仓库化规格、隔离 worktree、执行计划、测试并集和严格
> PR 门禁能够组成一个最小可用的并行 Harness；共享热点仍需显式整合，且整合结果必须当作
> 新提交重新验证。

当前证据不支持：

- “并行一定比串行更快”；
- “更多智能体一定提高吞吐”；
- “测试全绿即可自动判断任意冲突语义”；
- “现有 Harness 已适合大型项目或高冲突改造”。

## 6. 后续候选，不代表已决定

1. 为执行计划增加可选的开始/结束计时字段，下一次形成可比较的吞吐证据；
2. 评估轻量目录地图一致性检查，防止新增入口后文档过期；
3. 评估单一 Windows 验证入口，减少多层 PowerShell 环境变量转义；
4. 选择一个依赖更少共享热点的并行切片，与本轮 4 冲突结果比较；
5. 评估 GitHub push 与 PR 双重运行的收益和 CI 成本。

以上候选涉及 Harness 维护成本或验证语义，必须按 `AGENTS.md` 的权限边界先提供决策卡，
由学习者决定是否进入下一轮。
