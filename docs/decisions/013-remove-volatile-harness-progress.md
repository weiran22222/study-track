# 决策卡 013：移除导航中的易变 Harness 进度

状态：已批准

日期：2026-07-28

## 问题

`AGENTS.md` 的“当前阶段”硬编码了没有明确版本协议的 `Harness v14`，并手工汇总
`AC-01～AC-16` 的完成状态和一系列已完成事项。这些内容会随产品演进失效，也重复了
`SPEC.md` 与历史工件的职责，使稳定导航重新累积维护成本。

## 人类批准

用户于 2026-07-28 明确批准移除无明确版本协议的 Harness 版本号和手工 AC 计数，并接受
以 `SPEC.md` 唯一权威与 `verify` 机械验收入口的稳定说明替代易变进度快照。变更保持产品、
架构、验收和门禁语义不变。

## 决定

- `AGENTS.md` 不再维护 Harness 版本号、验收项计数或已完成功能清单；
- 当前产品行为与验收标准以 `SPEC.md` 为唯一权威；
- `verify` 是机械验收入口，具体流水线继续以 `ARCHITECTURE.md` 为准；
- `AGENTS.md` 只保留稳定导航、边界、工作流和门禁约定，历史理由从文档索引按需查阅。

## 取舍

默认入口不再提供一段进度快照，但避免了多处同步和无协议版本漂移。当前事实仍可从
`SPEC.md`、`ARCHITECTURE.md` 和实际 `verify` 结果获得，历史理由仍可从文档索引发现。

## 不变边界

- 不改变产品行为、架构约束、验收标准、自动测试、CI 或分支保护；
- 不削弱受保护 `main`、必需 PR、`verify` 或最终 `main` 验证；
- 不删除或改写既有决策、计划、证据和复盘；
- 不删除 `AGENTS.md` 中有价值的稳定能力、风险分级或门禁说明。

## 单 PR 验收

- `AGENTS.md` 不再包含 `Harness v14` 或手工 `AC-01～AC-16` 完成计数；
- `AGENTS.md` 明确 `SPEC.md` 的唯一权威职责和 `verify` 的机械验收职责；
- 本决策卡可从 `docs/README.md` 发现；
- 文档导航测试与 JDK 21 完整 `.\mvnw.cmd verify` 通过；
- 决策卡、导航调整和索引更新位于同一个受保护 PR，不创建执行计划、独立证据或复盘。
