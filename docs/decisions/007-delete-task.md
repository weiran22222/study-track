# 决策卡 007：永久删除单个任务

状态：已验证

日期：2026-07-27

## 问题

StudyTrack 可以添加、查看和完成任务，但用户无法删除错误创建或不再需要的任务。当前
`SPEC.md` 明确把删除排除在版本范围外，因此智能体不能在没有人类决定的情况下实现。

删除会永久改变持久化状态，并引入不存在任务、损坏数据、写入失败、ID 是否复用和确认方式
等产品语义，属于第三级变更。

## 候选方案

### A. 不增加删除

保持当前最小产品范围。

- 收益：没有破坏性操作和额外维护成本；
- 成本：错误任务无法清理。

### B. 软删除或回收站

保存删除标记，并支持隐藏或恢复。

- 收益：可以恢复误删；
- 成本：需要修改数据格式、查询语义和迁移策略，明显扩大范围。

### C. 永久删除单个任务

使用显式的 `delete <id>` 命令从 `tasks` 数组移除一项，保持现有 JSON 结构。

- 收益：满足最小删除需求，不引入迁移；
- 成本：操作不可恢复，必须严格保护失败路径。

选择本方案。

## 人类决定

学习者于 2026-07-27 明确批准：

1. 把永久删除单个任务加入当前产品范围；
2. 删除后 `nextId` 保持不变，任何历史 ID 永不复用；
3. 第一版不进行交互确认，也不要求或接受 `--force`；
4. 删除失败必须保留原始数据。

## 产品协议

- 命令：`delete <id>`；
- 成功：stdout 输出 `Deleted task <id>.`，退出码 `0`；
- 不存在：stderr 输出 `Task <id> not found.`，退出码 `2`，数据不变；
- 非整数 ID：由 Picocli 返回参数错误和退出码 `2`；
- 数据文件不存在：按任务不存在处理，不创建文件；
- JSON 损坏或持久化失败：退出码 `1`，原文件保持完整；
- 可以删除未完成或已完成任务；
- 删除一项不得改变其他任务的内容和相对顺序；
- 删除最后一项后保留合法空任务集合及原 `nextId`。

权威行为已经写入 `SPEC.md` 2.6 节和 AC-14。

## 非目标

- 不实现编辑、软删除、回收站、恢复或批量删除；
- 不增加交互确认、`--force` 或其他删除选项；
- 不修改 JSON 字段或执行数据迁移；
- 不改变现有命令的输出和退出码；
- 不修改 CI、分支保护、依赖或 Harness 权限。

## 架构约束

删除用例属于 Application。CLI 只能解析参数、调用 Application 并映射输出与退出码；
不得直接访问文件系统或 Jackson。Infrastructure 通过现有原子写入策略持久化新的任务集合。

## 验收

- `SPEC.md` 已明确删除协议和 AC-14；
- Application、Repository 和 CLI 分层保持正确；
- 成功、不存在、无文件、非整数、损坏 JSON 和写入失败路径有自动验证；
- `nextId`、其他任务、原始文件失败安全得到验证；
- JDK 21 下完整 `verify` 通过；
- 功能通过受保护 PR 合并并在最终 `main` 重新验证。
