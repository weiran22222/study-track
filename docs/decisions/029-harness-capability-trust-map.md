# 决策卡 029：建立 Harness 能力与信任边界图

状态：已批准，与本卡同一受保护 PR 实施

日期：2026-07-30

## 问题

当前权威文档分别定义目标、产品、架构、工作流和环境，历史索引保存形成理由，但缺少一个
稳定的第二层入口，把现有上下文与指导、机械反馈、编排状态、工具运行时边界、触发条件、
证据边界及已知部分覆盖集中导航。读者可能因而把“仓库记录了入口”误读成“当前运行时
具备能力”，或为定位已知缺口加载过多历史。

## 人类决定

用户于 2026-07-30 明确批准新增根级 `HARNESS-CAPABILITIES.md`。
本调整按第二级小型 Harness 决策实施，并与导航测试一起交付。

## 候选方案与取舍

### A. 继续从多份权威文档与历史索引自行拼接

- 收益：不增加文档表面；
- 成本：发现成本高，能力描述与信任边界容易混淆。

### B. 增加稳定、描述性的第二层能力与信任边界图

- 收益：按触发定位权威来源，并集中暴露证据边界和已有缺口；
- 成本：增加一份需要机械保护的导航文档，必须克制重复和漂移。

选择本方案。

### C. 维护工具、文件、插件与运行时状态的完整清单

- 收益：单页信息更细；
- 成本：高度易变、重复现有权威来源，并会制造运行时可用性和未来状态保证。

不选择。

## 决定

- 根级能力图只描述和导航当前仓库已定义的 Harness 表面、触发与信任边界；
- `AGENTS.md` 增加一个第一跳，`HARNESS.md` 声明其窄职责，`docs/README.md` 索引当前
  导航和本决策；
- `DocumentationNavigationTest` 检查发现性、本地链接、非权威措辞、核心类别、已知
  缺口入口，以及 `AGENTS.md` 不直链单个历史工件；
- 地图保持稳定类别和权威入口，不形成易变的工具、插件、文件或历史工件总账。

## 非目标与不变边界

- 不授予或修改智能体、工具、运行时、分支、远程仓库或发布权限；
- 不替代或重解释 `WORKFLOW.md`、`HARNESS.md`、`SPEC.md` 或 `ARCHITECTURE.md`；
- 不证明插件或技能可用、智能体身份、沙箱状态、远程状态或未来工作；
- 不修改产品行为、验收、架构、工具链、CI、脚本、依赖、环境配置或远程设置；
- 不新增执行计划、证据、反馈、能力、保证、指标或未来承诺。

## 验收边界

本地 JDK 21 环境检查、定向 `DocumentationNavigationTest` 和完整 Maven `verify` 只在实际
执行后作为 generator 自检报告；本决策不预写 evaluator `PASS`、required CI、PR、合并
或任何远程成功。
