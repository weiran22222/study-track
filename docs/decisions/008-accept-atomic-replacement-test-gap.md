# 决策卡 008：接受原子替换失败的直接测试缺口

状态：已接受

日期：2026-07-28

## 问题

永久删除任务的失败安全测试可以跨平台确定性地注入临时文件写入失败，并证明原文件字节
不变、临时文件被清理。但现有生产代码没有围绕
`Files.move(..., ATOMIC_MOVE, REPLACE_EXISTING)` 的可注入 seam，因此无法稳定直接触发
“临时文件写入成功、最终原子替换失败”。

这一缺口已经记录在删除功能的计划与证据中，没有被描述为已验证。

## 候选方案

### A. 接受并记录当前缺口

继续复用集中的原子写入路径，不增加生产抽象。保留清晰的证据边界和重新评估条件。

- 收益：避免为低概率故障增加生产复杂度；
- 成本：最终替换失败路径仍依赖代码审查、结构推理和既有原子写入设计；
- 风险：特定文件系统或运行环境中的替换失败行为没有直接故障注入证据。

选择本方案。

### B. 增加可注入替换 seam

抽象文件替换操作，测试时注入失败。

- 收益：可以稳定直接验证最终替换失败；
- 成本：增加只为测试服务的生产抽象、组合和维护负担。

当前不选择。

### C. 使用文件锁或权限制造平台故障

通过锁文件、只读目录或权限变化触发 `Files.move` 失败。

- 收益：不增加生产抽象；
- 成本：Windows、Linux 和不同文件系统行为不一致，容易形成不稳定 CI。

不选择。

## 人类决定

学习者于 2026-07-28 选择方案 A：接受并记录当前直接测试缺口，不为该低概率故障增加
可注入替换抽象或平台相关测试。

## 接受理由

- StudyTrack 是本地 Harness 学习项目，不是关键数据或高合规系统；
- 所有写操作集中复用同一临时文件加原子替换路径；
- 临时文件写入失败、原文件保护和临时文件清理已有直接自动验证；
- 缺口已经明确可见，不会被后续智能体误认为完全覆盖；
- 当前增加生产 seam 的持续成本高于新增证据的收益。

## 不变边界

- 不删除或弱化现有失败安全测试；
- 不把最终原子替换失败描述为已直接故障注入验证；
- 不因为接受该缺口而绕过任何现有 `verify` 或 PR 门禁；
- 后续若风险条件变化，必须重新评估，不能把本决定视为永久豁免。

## 重新评估条件

以下任一条件出现时，重新比较方案 A 与 B：

- 真实发生原子替换失败或数据丢失缺陷；
- 持久化代码被多个产品或实现复用；
- 数据丢失后果、合规要求或恢复成本显著提高；
- 项目已经引入统一文件系统抽象；
- 更多关键文件系统故障需要相同的可注入边界。

## 实施方式

本决定属于可逆、局部且不改变产品、架构边界、工具链或远程权限的二级 Harness 决策。
使用一个受保护 PR 更新决策、智能体导航和现有证据，不创建执行计划或归档 PR。
