# 决策卡 006：按风险分级的 Harness 变更流程

状态：已批准

日期：2026-07-27

## 问题

架构导航地图降粒度是一个可逆、单文件为主、不改变产品或验证语义的小型 Harness 调整，
但实际使用了决策卡、详细执行计划、实施 PR 和归档 PR。流程正确完成，却让治理成本明显
高于变更风险。

如果所有 Harness 变更都使用同一套最重流程，智能体会花费大量时间维护流程工件，学习者
也难以区分真正需要审慎治理的高风险决定和普通事实修正。

## 人类决定

学习者于 2026-07-27 明确接受：后续 Harness 变更按照风险、持续时间和协作复杂度选择流程，
不再对所有变更强制使用完整执行计划与独立归档 PR。

## 决定

### 第一级：事实修正

适用于错别字、失效链接、错误文件名、与仓库现状不符但不改变既定语义的修正。

- 使用一个受保护 PR；
- PR 描述问题、修正和验证；
- 不要求独立决策卡或执行计划；
- 仍必须通过适合该仓库的必需门禁。

### 第二级：小型 Harness 决策

适用于可逆、范围局部、不改变产品目标、核心架构边界、验收语义、智能体权限、工具链、
远程权限或显著持续成本的 Harness 调整。

- 人类知情；需要判断时先获得明确同意；
- 创建简短决策卡，与实现放在同一个受保护 PR；
- 默认不创建详细执行计划、独立证据文件或归档 PR；
- PR diff、审查记录和 CI 结果共同作为完成证据。

### 第三级：重大或多步骤变更

以下任一条件成立时使用完整流程：

- 改变产品目标、核心架构边界、验收语义或智能体权限；
- 修改工具链、远程仓库权限、数据格式或迁移策略；
- 引入显著持续维护或外部服务成本；
- 包含多个独立阶段、外部状态变化、并行智能体协作或高回滚成本；
- 无法可靠判断为第一或第二级。

该级别必须：

- 先获得人类明确批准；
- 创建决策卡和执行计划；
- 按阶段保存验证证据；
- 必要时使用独立归档变更，不能为了减少流程而提前声称未发生的远程结果。

## 不变边界

- 风险分级不能绕过受保护 `main`、必需 PR 或 `verify`；
- “改动文件少”不自动等于低风险，风险以语义、权限、外部状态和回滚成本判断；
- 智能体不得自行把第三级变更降级；
- 发现实际范围扩大时必须停止并升级流程；
- 无论级别如何，都不得把未执行的检查写成已通过。

## 本决策如何实施

本决策本身已由学习者明确批准，内容局部且不改变产品、架构依赖、工具链或远程权限。
因此使用一个 PR 完成决策卡、`AGENTS.md` 规则更新和验证，不创建执行计划或归档 PR，
作为第二级流程的首次实际验证。

## 验收

- `AGENTS.md` 清楚描述三级流程及升级条件；
- 现有产品、架构和验证规则不变；
- `main` 的 PR 与 `verify` 门禁不变；
- 本变更只使用一个受保护 PR；
- JDK 21 下完整 `verify` 通过。
