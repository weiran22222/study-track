# 决策卡 009：控制智能体导航中的文档熵

状态：已接受

日期：2026-07-28

## 问题

`AGENTS.md` 在每次任务完成后持续追加单个决策、计划、证据和复盘链接。每次追加都能提供
短期导航价值，但累积后会把智能体的默认入口变成历史手册，增加冷启动上下文并鼓励后续
智能体复制同一追加模式。

删除这些历史工件会丢失现状形成的逻辑原因，因此需要同时解决默认入口膨胀和历史知识
可发现性。

## 人类决定

学习者于 2026-07-28 明确同意：建立独立文档索引，因为决策事实解释现状的逻辑原因，
不能在清理导航熵时丢弃。

## 决定

- `AGENTS.md` 是稳定导航地图，只保存当前状态、有效边界、工作流和验证约定；
- `AGENTS.md` 不逐项登记已完成任务，也不直接列出单个已归档执行计划；
- `docs/README.md` 是历史决策、执行计划、证据和复盘的单一入口；
- 历史工件继续由 Git 保存，并通过索引按需渐进披露；
- 机械检查保护上述结构，并保证受管文档分类中的 Markdown 文件均被索引。

`SPEC.md` 和 `ARCHITECTURE.md` 描述当前有效的产品与架构事实。决策记录解释历史理由，
可能被后续决策取代，不得凌驾于当前规格和架构之上。

## 为什么不用总行数上限

不设置 `AGENTS.md` 最大行数。文件长度不是目标不变量：新的长期规则可能合理增加行数，
而压缩措辞也可能在未超限时降低可操作性。固定阈值既会误伤必要规则，也不能阻止短小但
无界增长的历史条目。

检查应保护语义结构：稳定入口必须存在、禁止已完成计划直链和历史追加措辞、受管历史
文档必须可从索引发现。

## 不变边界

- 不删除或改写既有决策、计划、证据和复盘；
- 不改变产品行为、验收标准、核心架构边界、工具链或远程权限；
- 不为了缩短文件而删减风险分级、工作流、验证、完成定义或失败反馈要求；
- 不绕过受保护 `main`、必需 PR 或 `verify`。

## 实施方式

本决定可逆、范围局部且不改变产品或架构语义，属于二级 Harness 决策。决策卡、索引、
导航精简和机械检查放在同一个受保护 PR；不创建详细执行计划、独立证据文件或归档 PR。

## 验收

- `AGENTS.md` 链接 `docs/README.md`，且不再逐项追加已完成任务；
- `docs/README.md` 分类索引现有决策、执行计划、证据、复盘和重要说明；
- 机械检查阻止同类导航熵重新累积，但不使用总行数阈值；
- JDK 21 下完整 `.\mvnw.cmd verify` 通过。
