# 决策卡 025：建立稳定的文档地图导航

状态：已实施（仓库内导航与机械检查）

日期：2026-07-29

## 问题

`AGENTS.md` 已链接产品、架构和历史索引，但“开始工作前”没有说明 `HARNESS.md`、
`docs/environment.md` 及四类历史目录的职责与读取时机。新进入任务的智能体仍需猜测
当前权威事实、工作约定、辅助说明和历史工件之间的优先级，也可能一次加载全部历史，
或把历史决定误当成当前事实。

增加导航时也不能回到逐项追加历史链接或维护完整文件清单的模式，否则每次历史工件增删
都会让默认入口漂移，并重复 `docs/README.md` 的索引职责。

## 用户选择

用户于 2026-07-29 明确选择在 `AGENTS.md` 开始工作区域附近建立稳定、紧凑的文档地图，
覆盖根级稳定文档、环境说明、中央索引与四类历史工件；历史理由继续通过
`docs/README.md` 渐进查阅。本调整按第二级小型 Harness 决策实施。

## 候选方案与取舍

### A. 保留现有三个入口，由智能体自行推断其余文档

- 收益：不增加导航或测试；
- 成本：职责、读取时机和当前事实优先级仍不清晰，冷启动继续依赖猜测。

### B. 增加稳定的第一跳地图，历史分类仍由中央索引展开

- 收益：一次说明稳定入口、职责和读取时机，区分当前事实与历史理由；历史文件增删不要求
  同步修改 `AGENTS.md`；
- 成本：增加一小段导航和少量稳定语义测试，需要克制内容避免复制协议。

选择本方案。

### C. 在 `AGENTS.md` 维护所有历史文件的完整清单

- 收益：单页可以看到全部历史工件；
- 成本：重复 `docs/README.md`，每次工件增删都要同步，扩大默认上下文并重新制造文档熵。

## 决定

- `AGENTS.md` 以文档地图作为任务第一跳，说明 `AGENTS.md`、`HARNESS.md`、`SPEC.md`、
  `ARCHITECTURE.md`、`docs/README.md` 和 `docs/environment.md` 的职责与读取时机；
- 地图说明 `docs/decisions/`、`docs/exec-plans/`、`docs/evidence/` 和 `docs/feedback/`
  的分类职责，但不直接列出其中单个文件；
- 当前事实优先从根级稳定文档读取；历史理由从 `docs/README.md` 选择相关工件渐进查阅；
- 地图只负责导航，不复制产品、架构、Harness、工作流或历史工件协议；
- 扩展 `DocumentationNavigationTest` 保护稳定入口、四类分类和渐进披露语义，但不让
  `AGENTS.md` 成为受管历史文件的完整清单。

## 不变边界

- 不改变产品行为、`SPEC.md`、`ARCHITECTURE.md`、`HARNESS.md` 或当前验收语义；
- 不改变智能体权限、分支规则、脚本、CI、依赖、远程设置或部署；
- 不删除或改写既有决策、计划、证据和复盘，`docs/README.md` 继续是其中央索引；
- 不创建执行计划、独立证据或复盘，不把本地实现写成 evaluator、CI、PR 或合并事实；
- 不使用总行数、历史文件数量或完整文件枚举作为地图稳定性的机械门禁。

## 验收

- 文档地图覆盖十个稳定入口或分类的职责与读取时机，并明确四类信息的优先关系；
- 当前事实优先读取根级稳定文档，历史理由通过 `docs/README.md` 渐进查阅；
- 地图保持第一跳粒度，不复制协议、不逐项列出历史工件、不维护完整文件清单；
- 本决策可从 `docs/README.md` 发现；
- `DocumentationNavigationTest` 保护稳定入口、分类和渐进披露边界，所有本地 Markdown
  链接有效；
- JDK 21 环境检查、目标测试和完整 `.\mvnw.cmd verify` 通过。

以上验证结果只由实际执行后的 generator 自检与后续独立 evaluator 报告记录；本决策不
预写 evaluator `PASS`、required CI、PR、合并或远端状态。
