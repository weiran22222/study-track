# 决策卡 019：使用 Codex-managed Worktree/Handoff

状态：已批准

日期：2026-07-28

## 问题

决策卡 018 通过仓库脚本发现可能遗留的 linked worktree，但这种做法只在问题产生后增加
分类和清理成本。临时 worktree 的来源仍由智能体手工创建和管理，生命周期容易脱离任务
协调状态，也会让仓库长期维护一套与产品、构建和 CI 无关的本地审计器。

## 人类决定

学习者于 2026-07-28 明确批准：临时隔离和任务移交改用 Codex-managed
Worktree/Handoff；智能体不得为临时任务手工运行 Git worktree 的 add、remove 或 prune。
如果 Codex-managed 能力不可用，智能体必须串行工作并请求协调，不得自行创建临时
worktree。

## 决定与理由

- 从创建入口统一生命周期，比在仓库内持续维护遗留状态清理器更直接地消除问题来源；
- Codex-managed Worktree/Handoff 让隔离状态与任务协调保持关联，仓库无需解析本地 Git
  porcelain 或推断任务、PR 是否完成；
- 删除已被取代的审计脚本和静态契约测试，并从稳定导航中移除其发现入口；
- 保留决策卡 018 作为历史记录，并明确由本决定取代；
- 不新增执行计划、证据文件、CI 门禁、远程权限或外部服务。

## 范围与例外

- 本决定约束智能体为临时任务创建和管理 worktree；
- 永久 worktree 或由用户、管理员、IDE、外部自动化手工管理的 worktree 不由本仓库工具
  审计、清理或改变；
- 已存在的外部 worktree 如需处理，必须由其所有者明确授权并在仓库外协调；
- 本决定不改变产品行为、Java 架构、数据格式、构建工具链、GitHub 或分支保护。

## 回退触发条件

仅当 Codex-managed Worktree/Handoff 长期不可用、不能提供任务所需的隔离或移交能力，
或者新的合规与运维要求必须由仓库内工具审计 worktree 时，才重新评估。回退前必须由
人类重新决定范围、权限和验收；不得静默恢复被撤回的审计器或重新允许智能体手工管理
临时 worktree。
