# 决策卡 030：建立仓库 Markdown 本地链接一致性门禁

状态：已批准，与本卡同一受保护 PR 实施

日期：2026-07-30

## 问题与当前状态

仓库当前根级 Markdown 与 `docs/` 文档树中的本地链接处于干净状态，但这个事实主要依赖
人工维护和部分导航测试。新增、移动或重命名文档后，未被既有定点检查覆盖的相对链接
可能失效，直到人工阅读或后续任务偶然发现。

需要把当前干净状态固化为范围明确、可复现且失败后可直接修复的 Maven/JUnit 一致性
门禁，同时避免维护一份会随文件增删而漂移的硬编码文件清单。

## 人类决定

2026-07-30，用户在获知所选范围是“仓库 Markdown 本地链接一致性门禁”后回复
“继续”。这构成对本次第二级小型 Harness 决策及其局部实施范围的明确同意。

## 候选方案与取舍

### A. 保持人工检查和既有定点导航测试

- 收益：不增加测试代码或构建时间；
- 成本：覆盖取决于人工记忆和硬编码入口，仓库其他 Markdown 的失效链接可能长期沉默。

### B. 为所有 Markdown 文件维护硬编码清单

- 收益：覆盖对象显式可见；
- 成本：每次文档增删都要同步更新清单，清单本身制造新的漂移与维护负担。

### C. 动态发现仓库 Markdown，并在 Maven/JUnit 中检查相对本地目标

- 收益：文件增删自动进入覆盖，检查只依赖当前 checkout，能复用既有 `verify` 入口和
  失败反馈格式；
- 成本：测试需要维护一段轻量 Markdown 链接识别逻辑，且只检查目标存在性，不判断
  文档内容质量或锚点语义。

选择方案 C。

## 决定与精确覆盖

新增 `DocumentationConsistencyTest`，并由 Maven/JUnit 的现有测试生命周期执行：

- 动态发现仓库根目录直接包含的 `*.md`，以及 `docs/**/*.md`，不维护文件账本；
- 对每个普通 Markdown 行识别链接文字括号匹配且紧接 `(` 的内联链接或图片链接；目标支持
  反斜杠转义、平衡括号、尖括号包裹及空白后的可选标题，从链接所在文档的目录解析；
- 在解析前移除 `#` 及其后的锚点；纯锚点链接不检查；
- 忽略带 URI scheme 的链接、协议相对链接和站点根相对链接，不访问网络；
- 顶层或最多三个前导空格的 fenced code block 中的示例不作为实时链接；
- 路径必须留在仓库内，并以精确大小写解析到当前 checkout 中实际存在的文件或目录；
- 文档和链接按稳定顺序处理；失败信息包含 `Location`、`Invariant`、`Reason`、`Fix`、
  `Recheck` 与 `Authority`。

这项检查只使用 Java 标准库、当前文件系统和既有 Maven/JUnit 入口，不读取 Git 状态，
不调用网络，也不增加依赖。

## 非目标与不变边界

- 不验证外部链接可达性、标题锚点是否存在、Markdown 风格、内容正确性或文档质量；
- 不扫描根目录和 `docs/` 之外的 Markdown，也不扩展到产品数据或其他文件格式；
- 不新增定时漂移扫描、质量评分、自动维护 PR、外部服务或远程状态检查；
- 不保证运行环境、工具、插件、技能、网络、远程权限或未来执行状态；
- 不改变产品行为、验收语义、核心架构、依赖、CI、脚本、权限、分支或发布规则；
- 不新增执行计划、证据文件或反馈文件，也不把本地绿色检查预写成 evaluator、CI、PR、
  合并或 Harness 正向效果结论。

## 验收边界

本地 JDK 21 环境检查、定向 `DocumentationConsistencyTest`、完整 Maven `verify` 与
`git diff --check` 只有在实际执行后才能作为 generator 自检报告。门禁通过只证明本次
checkout 中已覆盖 Markdown 的相对本地链接目标存在，不证明上述非目标。
