# 执行计划 006：建立环境自举反馈闭环

状态：已完成

## 背景

本计划执行
[决策卡 001](../../decisions/001-environment-bootstrap.md)。它是第一次反馈复盘后选定的
Harness 改进，不改变 StudyTrack 的产品行为。

## 目标

让只获得仓库、不继承父对话的新智能体能够：

1. 找到唯一的环境自检入口；
2. 在默认 Java 版本错误时获得精确反馈；
3. 在 JDK 21 可用时验证 Maven Wrapper；
4. 知道接下来应运行的统一验收命令。

## 范围

- Windows PowerShell 环境自检；
- macOS/Linux POSIX shell 环境自检；
- 环境说明文档与 `AGENTS.md` 导航；
- CI 接入；
- 关键环境契约的低成本回归检查。

## 非目标

- 自动安装或升级 JDK；
- 修改系统 PATH、用户配置或全局 Maven 配置；
- 提交机器专属 Maven settings；
- 解决所有代理、证书或镜像问题；
- 把本地缓存构建冒充为干净机器冷启动；
- 修改产品功能、数据格式或分层架构。

## 实现约束

- 不硬编码本机 JDK、Maven、用户目录或私有镜像路径；
- 自检应快速失败，不先运行完整测试套件；
- 失败信息遵守 `AGENTS.md` 的失败反馈要求；
- PowerShell 与 POSIX shell 的环境判定语义保持一致；
- Maven 必须通过仓库 Wrapper 调用。

## 验收场景

1. 当前默认 Java 17 下运行 Windows 自检：非零退出，并报告检测到 17、要求 21、修复方向、
   文档位置和验证命令；
2. 使用 JDK 21 运行 Windows 自检：Java 与 Maven Wrapper 检查通过；
3. CI 工作流在完整 `verify` 之前调用 POSIX 自检；
4. 自动回归检查能够发现自检入口、CI 调用或环境文档被意外移除；
5. 使用 JDK 21 运行完整 `verify` 通过。
