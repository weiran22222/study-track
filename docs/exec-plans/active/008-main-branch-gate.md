# 执行计划 008：验证 main 的 PR 合并门禁

状态：进行中

## 背景

本计划执行
[决策卡 003](../../decisions/003-main-branch-gate.md)。它把已经运行成功的 CI 从
事后报告器升级为合并前守门人。

## 实施顺序

1. 在 `main` 尚未保护时提交并推送本决策与计划；
2. 将远程仓库改为 Public；
3. 为 `main` 配置批准的 Branch Protection 参数；
4. 只读回查远程配置；
5. 创建测试分支与文档证据提交；
6. 推送测试分支并创建 PR；
7. 观察 `verify` 从运行中到成功，以及 PR 的可合并状态；
8. 尝试直接推送 `main`，确认远程拒绝；
9. 通过受保护流程合并 PR；
10. 回查最终 `main` 与门禁状态并关闭计划。

## 实现约束

- 不上传新的敏感信息；
- 不降低现有 CI；
- 不配置审批人数、签名、部署或合并队列；
- 不通过管理员权限绕过门禁；
- 测试直接推送时只使用无产品影响的证据提交；
- 若 GitHub 返回与预期不同的能力或错误，停止扩大变更并记录真实反馈。

## 验收场景

1. 可见性从 Private 变为 Public；
2. Branch Protection 参数与决策卡完全一致；
3. 测试 PR 自动触发 `verify`；
4. `verify` 完成前 PR 不可合并；
5. `verify` 成功后 PR 可合并；
6. 直接推送 `main` 被拒绝；
7. PR 合并后的 `main` 远程 CI 成功；
8. 仓库中的计划、决策和复盘包含远程证据。

仓库可见性和合并权限属于重大外部状态。只有本决策卡列出的变更获得授权；任何额外公开内容、
付费套餐、协作者权限、审批人数或安全策略变化都需要新的明确决定。
